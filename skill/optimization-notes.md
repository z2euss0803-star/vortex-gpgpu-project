# 从现有技能提炼的改进

本技能包是可移植的优化版本，不直接覆盖用户当前安装的技能。提炼的是已验证方法和适用边界，未复制其他技能包的专属工具、脚本或许可声明。

| 参考的现有技能/方法 | 保留的有效做法 | 本次改进 |
|---|---|---|
| vivado-offline-build | 工具/工程身份、独立run、自然退出、综合/实现/导出分门验收 | 将原文中“按用户要求排除新仿真”的局部约定改为按当前硬件/软件变更分类；不会默认所有工程都跳过仿真，也不绑定Vivado2020.1或A/B主机 |
| engineering-space-manager | 区分逻辑字节和卷空间、共享主机归属、未知不当空闲、按项目阈值 | 补充参数化只读政策检查，限定资源例外的stage/host/授权来源，保留正常REFUSED；具体2/3或4/8GiB数字不成为通用默认 |
| ChipForge的仿真流程 | RTL与测试平台对应、保留真实仿真结果和波形依据 | 不要求任意工程先安装Windows.exe、建知识图谱或无条件生成全量VCD；按工具能力和项目验收确定波形范围和必需证据 |
| skill-creator及技能测试方法 | 明确触发范围、渐进披露、测试工具的实际行为 | 核心只用标准name/description，不加入特定客户端allowed-tools、用户目录或UI元数据；每项独立复制可用 |
| 本项目冻结交付与性能审计 | 字节身份、重复回执去重、观察窗和硬件周期区分 | 提炼标准JSON输入与Python只读工具，用其他工程/设备名称、未知字段和边界条件演练，不硬编码R13或S8 |

## 未改变的东西

工程冻结源码、模型、bit/XSA、旧R13 Release和现有本机技能目录均不由本技能包修改。项目特有的地址、位宽、停止约定、精度门槛、资源门和有效授权应由调用方提供；不得把示例当当前工程事实。

## 如何继续优化

先保留实际失败输入、预期输出和原日志，再新增能复现问题的测试。只修正经示例证明的缺口，避免为每次意外增加一条永久规则。更换客户端时优先检查技能发现路径、脚本解释器和权限差异；格式检查不能替代真实客户端验证。
