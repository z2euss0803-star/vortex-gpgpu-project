# 恢复边界与方法

本文件只说明恢复流程，未执行媒体、设备、复位或PL操作。

1. 每次媒体写入前重新识别B的物理磁盘、介质、分区、卷和盘符，区分SD与外置SSD。历史Disk号或序列号不能直接沿用。
2. 将本次卡上`BOOT.BIN`、`boot.scr`和`image.ub`备份到独立目录，保存文件长度、SHA256、识别快照和读操作退出码。备份核验失败或出现介质I/O不稳定时不写卡，不格式化、重新分区或自动修复。
3. 恢复时选用同一次备份的完整匹配集合，重新核对当前介质身份。只恢复当时获准的启动文件，保留分区表和无关第二分区；回读核验并安全弹出。
4. 若是运行时错误，先保存首次errno、日志、完成/退休快照、build-id、程序和模型/输入身份。QUARANTINED、未知排空或未退休对象不能通过清标志、强制释放、扩大看门狗或关闭guard制造恢复成功。
5. 新现场恢复权限按届时授权核对。需要重新上电、复位或重配置PL时，不将离线媒体授权替代这些操作权限。

当前恢复对象是本次S8联合flags4的完整匹配集合，或本次卡写入前准确核验的完整备份。旧flags1/2集合仅作各自历史恢复，旧868bed60/34c55448不能替代当前联合启动链；不能混配BOOT、FIT、DT、程序或硬件身份。

工程缓存恢复通过对应归档`members.json`映射回原路径；先核对完整归档和成员身份，仅恢复缺失且未被新文件替代的条目。禁止覆盖C当前使用的内容或更改共享下载/sstate。源码、SDK、模型、有效启动集合和原始失败证据优先保留。

本次已归档的旧HOST输出、旧编译/链接中间物、已淘汰快照、旧成功FIT导出副本、私有解析缓存和一次性传输helper，在各自原始成员映射中恢复；原始失败日志保留。SDK1626保护清单及当前KS/KDEV接口、实际391项内核输入/77驱动对象、有效Image/vmlinux/DT、工具链、源代码、模型和C使用内容优先保持。恢复不得覆盖新的文件或改变共享downloads/sstate。
