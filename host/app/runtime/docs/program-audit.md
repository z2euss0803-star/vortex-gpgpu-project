# GPU program boundary, 2026-10-09

Production whitelist contains only archived `vendor/h0/vecadd16.h` (22 RV32 words, 88 bytes) at GPU PC 0x10000000. Its embedded common entry is absolute 0x10000010. Trailing bytes must be zero, at most 4096 bytes total. Relocation, mutation, unknown CRT and ELF bytes are rejected. The program reads three 32-bit addresses from its startup argument: {a,b,c}. H0 has 4 cores × 4 warps × 4 threads: MHARTID is global, so it stores **64** one-word sums, not 16 total. Independent delivered gpgpu_hw.h specifies VEC_COUNT=64, and host_logic.c checks that full extent. It executes diagnostic FENCE and stops; no generic CRT, `_Exit`, or performance writes to low PS addresses. Every array address must resolve to a current DATA object for **256 bytes** before START. FENCE 0x10030000/64 remains exclusively reserved.

This is a source/instruction review of the fixed diagnostic, not execution proof. The raw whitelist is tested against the separate archived source header and mutated/address-negative cases. H0 bit/source binding uses r4 delivery source manifest; exact current bit and MMIO ordering still require board evidence. Generic RV32 programs and Mosaic remain D4-blocked until their CRT/linker/hidden writes are audited. This whitelist does not establish hostile-program isolation.

Offline public API test deliberately uses a **different**, explicitly synthetic ABI {count,a,b,c} and opaque 16-byte dummy payload. CPU model computes addition; it does not decode RV32 instructions. Do not submit that synthetic fixture to the real driver; production whitelist rejects it.
