# Linux 神经网络运行时、调度器与通用 GPU 驱动设计规格

**版本：NNRT-DESIGN-1；状态：用户于2026-10-21批准书面规格；详细实施计划待审，升级实现尚未开始。**

本规格把用户提供的方向转为工程合同，不将附件中的旧状态当作当前事实。2026-10-21 已有部分板端证据：DP 独立 RAM 候选色条与恢复通过，Mosaic 首层卷积失败，重新上电后 HUNet 在选择阶段返回 EBUSY。因此不能继承“双应用真板全部通过”。

## 1. 目标、顺序与范围

目标是在冻结 Vortex 硬件上，将模型图、量化、CPU/GPU 分工与调度迁入用户态；驱动保留设备独占、内存范围、DMA、程序准入、作业状态和生命周期检查。支持范围内的新模型通过模型包接入，最终用“同一驱动二进制运行新增小网络”验证扩展性。

用户确认的约束：单设备所有者、多请求有界队列、单 GPU 活动作业、CPU 线程池；保留静态图优化、旧 ABI、旧程序身份、每核 8×8 原生 signed INT16 PE、模型分别冻结的数值参考和阈值。无硬件抢占、多上下文、MMU 隔离或 DMA/计算重叠的默认假设。

按依赖分三条工作线，分别验收：

1. **P0 当前故障修复**：网络与 DP 已验证修复固化；HUNet 切换的冷 CDMA 状态回归及拒绝日志；Mosaic 超限原因与受控分块诊断。P0 失败和当前原始记录永不覆盖。
2. **P1 行为等价迁移**：先在旧驱动上封装，加入模型包、图准入、张量规划、调度及计时。它仍受旧驱动支持范围限制，不能提前宣称通用模型接入完成。
3. **P2 通用机制与优化**：独立版本化的受控程序、对象、异步完成和批量接口；HUNet/Mosaic 接入；用新小网络验证无内核修改；常量驻留和减少交接等优化逐候选进行。

P1/P2 可在主机继续开发，但不得以其完成来关闭 P0 的真板故障。现场计算和发布以 P0 对应准入门满足为条件。

不包含任意 ONNX 自动导入、训练、任意不受信代码、GPU 抢占、多 GPU、RTL 修改、3D 渲染、桌面环境或未经实测的零拷贝承诺。

## 4. 方案比较及选定架构

| 路线 | 收益 | 代价与适用性 |
|---|---|---|
| 继续增加模型专用驱动分支 | 少量旧模型接入成本低 | 新模型继续重编内核，无法达到扩展验收，不采用作目标架构 |
| **统一用户态服务＋受控通用驱动** | 复用冻结硬件，模型可扩展，能够分阶段等价迁移 | 需要清晰的程序准入、对象和生命周期合同；本规格采用 |
| GPU 多上下文／抢占／直接通用 OpenCL | 潜在生态与并发能力 | 当前硬件与驱动证据不足，增加硬件和安全范围，留待独立项目 |

选定的数据流：B 客户端 → 板端 `vxnn-service` → 模型包准入／静态图执行计划 → 有界调度器 → CPU 池或 `libvxnn-gpu` → 独占通用驱动 → 冻结 GPU。完成并核验的不可变结果经 DP 适配器显示。旧 `vxl_demo`、旧 ioctl 和旧程序仍可独立启动，与新服务互斥。

服务是唯一设备所有者，B 客户端不直接拿设备 fd。采用本地 Unix socket 与既有 SSH 转发传输，不为升级开放新公网服务。客户端请求格式另设版本，不复用旧 JSON 的未声明字段。

## 5. 模型包、算子注册与静态计划

模型包 v1 包含 `manifest.json`、`graph.json`、资产及其 SHA 清单、`program-requirements.json`、`numeric-contract.json`、冻结参考／已知失败清单。先支持解包后的私有只读目录；打包导入拒绝绝对路径、`..`、符号链接、硬链接、设备、FIFO、重复成员和超额解压。每个文件有长度、内容摘要、类型和角色。

`model_id` 使用已规定字段的规范化 JSON 内容 SHA；模型版本是说明字段，不能代替摘要。权重、输入前处理、输出后处理、形状、布局、W/A类型、48位累加、舍入、饱和、反量化、FP32统计顺序分别显式声明。每个模型的验收规则独立，禁止扩大 HUNet 历史偏差豁免到 Mosaic。

算子注册以 `(name, semantic_version, implementation_sha)` 为键。实现声明类型／布局／形状谓词、量化规则、工作区、读写张量、CPU/GPU位置、程序需求、数值参考及融合约束。未支持组合在准入阶段拒绝，不静默换 CPU、降精度或换归一化。

准备阶段执行拓扑排序、环路拒绝、静态形状推导、带溢出检查的字节计算、布局检查、张量生命周期、可选融合和分块。`plan_id` 纳入模型、算子实现、优化开关、程序、硬件能力与规划器版本。只在准备阶段做这些工作，运行阶段不重新推导整图。

动态形状第一版仅允许模型包列出的有限 profile；每个 profile 独立生成计划。不能用“最大分配足够”代替动态形状的算子与数值验证。

第一阶段保留旧 HUNet program9 和 Mosaic program12 的封装适配器；S8 program11 和其余历史ID保持原义。程序9的固定图不能因封装成算子就宣称支持任意新图。后续独立通用算子程序使用新命名空间和摘要，不改写旧编号。

## 6. 张量与模型驻留内存

张量对象记录 dtype、layout、shape、字节数、对齐、只读／可写、域、所属请求、代际、生产者和最后消费者；CPU、DMA、GPU、DP 的使用期全部进入生命周期。

CPU VA、PS DMA、GPU32 和 PL 40位总线地址严格分开。复用当前硬件映射：PS pool 0x10000000／1 MiB，PL base 0x500000000／2 GiB；实际分配还扣除代码、栈、表、fence和保留区。用户态对驱动只提交受管句柄、偏移和长度，不以裸指针替代设备地址。

不重叠生命周期可复用同一 extent。可写别名、仍被CPU/GPU/DMA/DP引用、未知完成状态、取消未排空对象不可复用。默认不做 in-place 优化，只有注册表声明并由依赖分析证明才允许。

只读权重和程序按内容身份驻留；装载后驱动封存对象，拒绝所有写入口，提交时验证代际和权限。首次装载和重新装载校验完整内容。文件名相同不构成缓存命中；CPU侧私有副本和GPU侧句柄的封存身份也须一致。

物理设备容量由能力查询获得，第一版最多64个活设备对象，与现有64对象上限相容。大的张量工作区可作为一个受管arena，提交时对实际引用的子范围逐项检查；用户态规划不能代替内核范围检查。

驻留最多2个模型，但不承诺其同时驻留必然成功；总GPU容量和保留区约束优先。CPU服务内存预算默认1 GiB，输入排队字节默认64 MiB；大输入通过显式分配预算或拒绝，不能无界缓冲。资源不足返回清晰错误，不自动删除证据。

## 7. 请求调度、CPU 池与取消

第一阶段最多8个排队请求、1个活动图请求、1个GPU活动作业；FIFO，请求不可绕过队列无界占用资源。活动图内部按依赖派发，CPU工作池默认4线程，上限为配置与在线CPU数的较小值，禁止算子内部再无界开线程。旧四线程GELU适配到驻留池时保留原分段、erf数学和线程浮点环境。

第一版允许后续请求进行受预算的包解析／不可变CPU预处理；不跨请求交错共享GPU状态和可写张量。逐节点跨请求公平调度留到证明状态隔离后的独立优化。

状态明确分开：

- 请求：`CREATED → VALIDATED → QUEUED → RUNNING → COMPLETED/FAILED`；排队可到 `CANCELLED`；活动请求先到 `CANCEL_PENDING`，安全排空后才到终态。
- GPU作业：`PREPARED → SUBMITTED → RUNNING → COMPLETED/FAILED → REAPED`；未知是否停止的故障保留 `PINNED_UNKNOWN`，不能当可回收终态。
- 设备：`READY → BUSY → READY`，硬件/传输故障到 `FAULTED/QUARANTINED`。

排队取消移除请求并释放未提交对象；活动取消仅禁止后继派发，不能中止当前GPU或立即释放缓冲区。超时和进程退出不等于硬件停止；RPC断连也不取消推理。

依赖失败后后继标记 `SKIPPED_DEPENDENCY`，不发送GPU任务。设备故障后停止该设备派发、保留被引用对象和事件，排队请求标记设备不可用，不让服务自动复位、切换程序或再次提交故障任务。

请求幂等键为 `(boot_id, client_id, request_id)`，重连同键同摘要返回原状态，同键不同输入拒绝。第一版当前boot保留最多256条终态索引；满时先导出、显式回收或拒绝，不静默删除未取证记录。重启后原请求标记状态未知／前代请求，不自动重跑。

## 8. 旧 ABI 与新通用接口

旧ABI major1的176字节 envelope、`'V'`编号1～22、64～69及旧profile/program保持字节和语义；32位compat继续按实际能力拒绝，不能仅强制转换指针。以现有头文件黄金SHA和实际旧测试验收兼容性。

**新接口候选分配**：同设备 `/dev/vortex0`、独立 major2 envelope和 `'V'`编号0x80～0x8b。实施T02必须重新扫描全库和当前候选确认无冲突；编号仅在本规格命名空间中预留，未实施的头文件不是已发布ABI。

| 编号 | 职责 |
|---|---|
| 0x80 CAPS | 硬件/ABI/地址域/对齐/对象、作业、证据上限；明确 preempt=false、contexts=1 |
| 0x81 BUFFER_CREATE | 受管对象分配、用途、域和权限 |
| 0x82 BUFFER_INFO | 查询长度、权限、代际和被引用状态；不公开任意MMIO能力 |
| 0x83 BUFFER_COPY | 有界CPU复制或受管对象间DMA及缓存同步 |
| 0x84 BUFFER_RELEASE | 无在途引用时释放，过期句柄拒绝 |
| 0x85 PROGRAM_LOAD | 管理员准入程序、范围/入口/摘要/能力和封存 |
| 0x86 PROGRAM_INFO | 查询程序身份和驻留对象 |
| 0x87 PROGRAM_RELEASE | 活动作业未引用且空闲后卸载 |
| 0x88 SUBMIT_BATCH | 提交1～32个已验证作业描述符；全批验证／取引用后原子入队 |
| 0x89 WAIT | 有界等待已存在的完成／失败，不把等待超时当执行超时 |
| 0x8a COMPLETE_REAP | 按完成序号读取并显式回收记录，读取失败不得丢记录 |
| 0x8b FAULT_INFO | 查询故障、未排空对象、所需恢复条件和分项快照 |

新envelope定长128字节：16字节头（major、size、flags、reserved），9个对齐64位字段（device_generation、handle、object_generation、offset、length、user_ptr、cookie、sequence、payload_bytes），state和有符号result共8字节，reserved[8]共32字节。用静态断言、黄金字节和AArch64测试冻结偏移，不含内核指针。所有输入保留位为零，指针只用于有界copy_from/to_user，不成为GPU地址。

请求中的对象/程序句柄为代际标识，内核校验fd所有者、设备代际、对象代际、权限、偏移、长度、对齐和溢出。代际溢出拒绝继续，不回绕复用。用户态图依赖最终转为内核可验证的作业内存引用；内核无需理解模型层名。

通用接口仍是**受信程序执行机制**：程序包由管理员纳入受控catalog并封存，用户请求不能添加代码摘要或任意改入口。内核核对代码/只读表/入口/参数区及已注册的引用schema。没有硬件MMU时，普通范围检查并不能证明任意机器码不会越界；因此第一版不声称能隔离恶意GPU程序。这个限制必须出现在能力和发布说明中。

算子语义和模型合法性在用户态；涉及设备安全的参数范围、读写权限、资源预算、程序完整性和对象生命周期仍在驱动。程序catalog可由受控部署更新，不把新模型名、图拓扑、固定层数或特定权重摘要继续编进通用驱动。

## 9. 异步完成与批量提交

现有驱动没有 `.poll`，worker使用5ms delayed work，旧WAIT也有1～2ms休眠；这些是本次源码事实，不是已测性能占比。

新驱动使用同一锁保护对象、活动作业和有界完成环；新增 wait queue 与 `.poll`。硬件无已验证IRQ时仍由受控worker观察状态，再唤醒poll/epoll，不能把软件事件称作硬件中断。完成记录发布在状态和证据写完之后，配套读写屏障。

最多32个待派发GPU描述符、64个未回收完成记录；容量在CAPS返回。批量提交先复制完整描述符，全部验证并取引用，容量足够才接受；任一描述符非法则整批不入队、不运行。已接受批次执行途中失败时，之前成功记录保留，失败作业及后继逐条有结果，后继不启动。

完成空间不足时停止接受／派发会造成记录溢出的任务；提前为已接受作业保留完成槽，不能丢证据。POLLIN为有完成／故障记录，POLLERR为设备故障，重复epoll唤醒不表示重复完成。

批内仍一次仅有一个GPU活动作业，每个保留原始周期、状态、guard、摘要和回收记录。减少ioctl不等于合并硬件任务或GPU并行。取消、copy_to_user失败、信号中断、重复reap、owner关闭分别测试引用保持和记录可重新读取。

## 10. HUNet、Mosaic 和 DP 迁移

HUNet先保持当前GPU程序、CPU erf路径、布局、融合语义、历史ROI和最终输出；新CPU二进制需独立数值准入，不复用旧flags7。默认关闭逐层诊断，只有首次新身份准入或定位获准时显式打开。与冻结历史失败逐字节一致分类为已知精度偏差，原ORT/R2仍如实报告。

Mosaic保持W16A16原生8×8 signed INT16 PE、48位累加、冻结权重/尺度/量化/反量化、正式21项参考及归一化兼容方案。FMA只允许已批准的InstanceNorm独立候选；调度迁移不引入新的数学顺序变化。完整1280×960结果、时间和显示仍待实际验收。

DP是独立结果消费者，仅接受已完成、身份匹配、长度/摘要正确的不可变结果对象。显示持有对象引用直到flip退休或恢复完成；不能由推理线程复用正在扫描的缓冲区。显示失败单独记录，不改写推理结果的数值状态。保留当前ARGB8888、≤60Hz选择及CRTC/路由恢复。

B控制工具增加模型查询、提交、请求ID、队列状态、排队取消、结果/错误导出；异步接口同时提供最终退出码，不能“提交成功”就报告推理成功。图形界面仍是轻量本地展示，不引入完整桌面。

## 11. 时间、数值与错误合同

统一事件键：run_id、boot_id、request_id、model_id、plan_id、operator_id、job_id、device_generation、buffer_generation、source_id、status。Linux使用CLOCK_MONOTONIC；B网络时钟单独统计，不跨机相减。

记录：接收/排队/调度、包解析/校验、权重/程序装载、CPU预处理与各算子、池派发与等待、方向和字节数的DMA、guard/摘要/提交/状态轮询/交接/回收、每GPU作业raw_cycles及有效标志、结果转换/导出/DP。标注每个区间的父子关系和时钟域，累计忙碌、墙钟和关键路径分别报告。

GPU raw_cycles仅由实际硬件证据填写；离线、故障无有效完成、未运行均为null，失败计数观测另列。频率换算另列频率来源：当前只有配置核验，无仪器独立测频，不能写成物理频率校准通过。

首次／冷装载、热推理、模型切换、排队吞吐分别测试；关闭诊断性能数据不得混入逐层采集时间。正式样本数量在现场计划中确定，输出单次值、中位数、P95、样本数和失败，不预填加速比例。

错误目录至少有 identity.json、command.txt、stdout.log、stderr.log、exit.json、events.jsonl、metrics.json、result_manifest.json、failure.json。自然退出码与语义错误同时审计。回归、数值、工具编排、资源拒绝、取消、运行故障分别分类；每次纠错用新run_id并链接原失败。

用户最新允许失败后自行纠错；含义是留证后继续定位和独立复验，**不代表故障GPU可在未知状态自动重提、清除隔离、复位或重配置**。离线修复与构建可持续推进，实际现场恢复仍须有当时有效授权和安全依据。
