# Mosaic 第16层偏差：归一化参考冲突（2026-10-19）

关联：[已批准子计划B](../../../../60-输出/Mosaic-HUNet-DP实施子计划B-Mosaic原生INT16-2026-10-18.md)。本页是诊断记录，不改变数值合同。

## 已取得的因果证据

本次在 A（ry / RY\\13151）的 PyTorch 2.11.0+cu128、cuDNN 91900、RTX 3060 Laptop 上离线诊断。原始证据在 `evidence/demo/T05/investigation-20261019/`。不是 Vortex 或开发板运行，GPU 原始周期一律为 null。

1. 当前可移植实现采用 FP32 补偿归约、中心化总体方差、eps=1e-5、分步反量化及归一化，无 FMA。真实上游传播的前15层满足逐层阈值，但第16层仍失败：最大绝对差 0.1528167724609375，RMSE 0.016617360786211052，5703项超逐点阈值。旧失败目录保持不变。
2. 固定同一份第一层卷积输出，原参考的 CUDA/cuDNN InstanceNorm 与冻结的第一层输出逐字节一致；CUDA native InstanceNorm、可移植实现以及使用同一份 cuDNN 统计量但采用不同 FP32 应用顺序的输出均有低位差异。统计量也存在若干 ULP 差异，尚未证明差异仅来自 FMA。
3. 在独立进程中，只把真实计算链中的归一化替换为原 CUDA/cuDNN 实现，其余量化、直接 INT64 点积、逐步 FP32 反量化、布局、残差和阈值全部保持不变；不向计算链注入冻结的中间输出或统计量。16层全部逐字节相同，末层最大差和 RMSE 均为0，输出 SHA256 为 `86263295bf765c188e20521e5b7225955c0e17d58699034533b5e37a67357a4d`。这是归一化实现差异引发传播漂移的因果证据，不能作为可移植候选通过。
4. 单变量诊断将归一化乘法改为先乘 gamma、再乘 invstd，保持原统计量和其余链路不变。末层仍失败：最大差 0.1471099853515625，RMSE 0.016208876298801925，5299项超阈值。该诊断没有进入生产实现。

## 尚未闭合的问题

冻结的历史张量实际来自 CUDA/cuDNN，而子计划B要求平台独立的明确 FP32 顺序、禁用 fast-math/FMA。两者不能仅凭公式相同就认定逐步舍入语义相同。已有实验尚不能证明严格 FP32 实现一定无法满足原阈值，也不能证明允许单一 FMA 或更高精度就会修复。

原最终阈值 max_abs<=0.1、RMSE<=0.01 不变，历史失败不改为通过；不得调整量化比例、注入黄金中间张量、单独放宽第16层或隐去错误。当前生产实现未改动，T05/T08 数值门仍 OPEN，program12/匹配运行时及镜像不得因此标为完成。
