# HW4 新整机基线的启动计数器错误

领域 IC/FPGA；工具 Vivado/XSim 2020.1；器件 XCZU11EG。2026-10-06 本地采样，板卡未连接。

## 事实

- 新私有库来自 HW4 的 305 项冻结功能来源，未复用旧 R4 设计二进制。v1 的 Verilog/VHDL 编译退出 0；C 对象生成后，xsc 将 `-I` 传给归档工具 ar，导致归档失败。v1 保留且不重启。v2 复用同候选已完成库和 C 对象，仅执行正确归档、展开和仿真。
- v2 全设计展开成功。实际仿真在 5156、15468、25780、36092 ps，各出现 Icache/Dcache 的 counter overflow/underflow，共 16 条 Error。该 run 无论后续局部结果如何，都不能通过严格零 Error 门槛。
- 同步观察显示：前四个时钟沿局部 reset=X、size=X；36.092 ns 的 NBA 更新后 reset=1，46.404 ns 更新后 size=0。200 ns 的复位检查通过，随后 DDR 校准、CDMA 回环及第一轮三个 GPU vecadd 用例完成。这些局部 PASS 不抵消全日志 Error，也不是 Mosaic 算子或板端通过。
- [14:13:27 活动前缀快照](runtime_error_prefix_20261006_141327/manifest.json)绑定日志、VCD、state 和阶段退出记录。当时对象仍运行，快照只证明已复制的前缀，不能称为完整结束现场。[14:13:49 成功 CIM](runtime_error_process_20261006_1414.json)核实 worker 17112、xsim 7596、xsimk 31928 的命令行/创建时间/CPU/内存；没有操作任何进程。

## 因果与旧适配

原 `VX_pending_size` 的 wide-step 算术断言位于 `if(reset) ... else ...` 内。RTL 仿真初期 reset=X 时走 else，断言表达式含 X，因此报告 Error。初期状态不能解释为已发生有效事务后的真实计数器溢出。

旧回环明确使用 [SIMULATION 专用检查器](F:/obsidian-codex/codex/work/vortex_v23_dual_ddr_loopback_20261001/models/gpu_assertion/VX_pending_size.sv)：首次有效复位后启用算术检查，并拒绝此后未知 reset。原文件 SHA `1f032cc4992c844eab3f68ab2bce2d9687d43017f924f4b33d598e7734bb0f53`、检查器 SHA `6390e6d87e4e1dac1cd40dcbed5f63d3a70a18d849da4a29e16b4599c12a5290` 与 HW4 原模块及历史资格记录匹配。本轮组装遗漏了该检查器，导致原始启动错误再次出现。

已核对[旧故障注入结果](F:/obsidian-codex/codex/work/vortex_v23_dual_ddr_loopback_20261001/evidence/pending_assertion_candidate_v3/result.json)及其全部三项输入 SHA：正常序列无 Error，溢出、下溢、复位后未知 reset/incr 均被检测。输入未变，未重跑旧测试。去掉验证语句的功能 token 相等，原硬件源码、bit/XSA 不改。

v3 准备因默认 GBK 解码导致派生 token SHA 不符，在编译前拒绝；源码原始 SHA 一致。显式 UTF-8 复算得到历史 `ecc0609e...` 哈希。该准备现场保留在 [v3 拒绝记录](F:/obsidian-codex/codex/work/mosaic_hw4_soc_v3_20261006/evidence/static_preparation_rejection.json)。独立 v4 已固定解码、补入已验证检查器，并增加 200 ns 时两个检查器 armed=1 的检查；截至本页记录尚未启动。

## 下一步与边界

等 v2 自然结束，以新成功 CIM 核实退出，保存完整日志/波形/编译快照和身份后，才启动独立 v4 一次。只重编译检查器和新增 TB 观察、重新展开/仿真；已通过且输入不变的设计编译、C 归档不重复。v4 需严格日志、两轮复位/DDR/CDMA/GPU 基线及一次独立结束审计，然后才能启动新 Mosaic 两轮 20 作业回归。未更改架构或模型，板卡操作由用户执行。

复问：为什么 200 ns 复位检查 PASS，整机仍失败？答：检查点只证明那一刻复位已传播、计数器归零；此前 16 条 Error 仍是真实日志。必须保留失败并在新候选验证修复，不能过滤前 57 ns 日志或把局部 PASS 提升为整机通过。
